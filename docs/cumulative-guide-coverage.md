# Cumulative project guides, revision 3

Revision 3 teaches a complete route through each of the three published papers. It supplies a minimal HTML document once, plus empty text/code files. Every later activity identifies existing target files and the insertion or replacement location. Examples are small additions, not replacement projects. An already correct element is valid work and does not need to be retyped.

Every route begins with the document scaffold and static HTML, so external database setup never blocks the first coding activity. Kursy continues through HTML, CSS and its calculator before database, graphics and SQL work. Wędkowanie starts with HTML/CSS, then prepares its inputs, graphics and queries before PHP. Baza Smoków starts with HTML and its form, obtains the original descriptions and images when they become necessary, then teaches CSS, database work, PHP and tab switching. Page references remain in source-document order in the crosswalk below; teaching order is intentionally different. Missing banner/fish images during the first HTML activities are explicitly explained and supplied later.

The three routes contain 175 cumulative activities: Kursy komputerowe has 56 activities in 9 steps, Baza Smoków 66 in 11, and Wędkowanie 53 in 10. Counts include explicit manual preparation and delivery activities, not just automatically checked code.

The explanations and code fragments are independently authored teaching material. They are not CKE answer keys or an automatic official grade. The original PDF remains the source of requirements. Published revisions 1 and 2 are preserved in `allExamStudyGuides`; `examStudyGuides` selects revision 3 for new learning. No assignment version or old notebook is rewritten.

## Test evidence and limitations

`tests/study-project-content.test.ts` checks version preservation, a minimal initial project, absence of per-activity reset code, target/coverage consistency, paper-specific deliverables, runtime adapter identities, and HTML contracts against two independently authored code variants per paper. Targeted mistakes exercise actual HTML requirements. `tests/study-content.test.ts` retains the previous revision's executable fragment tests.

Private fixtures in `fixtures/study/projects.ts` include alternative JavaScript implementations, MySQLi/PDO PHP variants, SQL files and deliberate defects. They omit externally sourced graphics, the original `opis.txt` content and personal screenshots. Their label means valid code for the checked portions, not a certified complete submission. Runtime checks belong to `tests/study-checker.integration.test.ts`; fixture existence or static HTML matching is not evidence that those runtime tests ran. No automatic percentage is derived from this coverage map.
